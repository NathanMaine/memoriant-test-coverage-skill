# Semantic Test Coverage Skill

## Purpose

This skill teaches Claude Code to act as a semantic test coverage agent: scan a Python project, map which functions already have tests, identify what is missing, and produce ready-to-fill pytest skeleton files. The methodology mirrors the `NathanMaine/semantic-test-coverage-agent` reference implementation — AST inspection plus naming-convention matching — without any mutation-testing or proprietary scoring.

---

## When to Use This Skill

- A developer says "find what I'm missing in tests" or "generate test stubs for my project."
- A pull request or CI run reveals coverage gaps and you need to close them quickly.
- Onboarding: a new codebase needs a baseline of test skeletons before active development resumes.
- Continuous quality gate: periodically audit `src/` to ensure no new public function is test-free.

---

## Prerequisites

Before running this skill verify:

1. The project has a `src/` directory containing `.py` source files.
2. A `tests/` directory exists (may be empty — that is the point).
3. Python 3.8+ is available in the active environment.
4. `ast` is part of the standard library — no extra install needed for analysis.
5. For the generated skeletons: `pytest` should be installed (`pip install pytest`).

## Step-by-Step Methodology

### Step 1 — Discover source files

Recursively list every `.py` file under `src/`. Exclude `__init__.py` and any file whose name starts with `test_`.

```
src_files = glob("src/**/*.py", recursive=True)
src_files = [f for f in src_files if not f.endswith("__init__.py")]
```

### Step 2 — Extract function and method names via AST

For each source file, parse the AST and collect:
- Top-level `FunctionDef` and `AsyncFunctionDef` nodes.
- Methods inside `ClassDef` nodes (include class name for namespacing).
- Skip private helpers that start with `_` unless the user explicitly asks for them.

Output shape per file:

```json
{
  "src/analyzer.py": [
    {"type": "function", "name": "build_coverage_map"},
    {"type": "method",   "name": "Analyzer.scan_directory"}
  ]
}
```

### Step 3 — Discover existing test coverage

Recursively list every `test_*.py` file under `tests/`. For each, parse the AST and collect `FunctionDef` names that start with `test_`. Build a flat set of covered names using this heuristic:

- `test_build_coverage_map` covers `build_coverage_map`
- `test_analyzer_scan_directory` covers `Analyzer.scan_directory`
- Strip the `test_` prefix and match case-insensitively against the source name set.

### Step 4 — Compute gaps

```
covered_names = {strip_test_prefix(t) for t in all_test_functions}
gap_map = {}
for file, functions in source_map.items():
    missing = [f for f in functions if f["name"].lower() not in covered_names]
    if missing:
        gap_map[file] = missing
```

### Step 5 — Emit the gap report

Write (or print) a JSON gap report:

```json
{
  "scanned_at": "<ISO-8601 timestamp>",
  "project_path": "<absolute path>",
  "total_source_functions": 42,
  "total_covered": 31,
  "gap_count": 11,
  "gaps": {
    "src/generator.py": [
      {"type": "function", "name": "render_skeleton"},
      {"type": "function", "name": "write_output_file"}
    ]
  }
}
```

### Step 6 — Generate pytest skeleton files

For each source file that has gaps, generate a corresponding `tests/test_<module>.py` skeleton. If the file already exists, append only the missing stubs — do not overwrite existing tests.

Skeleton format per function:

```python
import pytest
from src.generator import render_skeleton, write_output_file


class TestRenderSkeleton:
    """Tests for render_skeleton — generated by memoriant-test-coverage-skill."""

    def test_render_skeleton_happy_path(self):
        # TODO: arrange
        # TODO: act
        # TODO: assert
        raise NotImplementedError("Implement this test")

    def test_render_skeleton_edge_case(self):
        # TODO: edge case
        raise NotImplementedError("Implement this test")
```

Rules for skeleton generation:
- One `class Test<FunctionName>` per function.
- Always include a `_happy_path` and an `_edge_case` stub.
- If the source function is `async`, emit `async def test_...` and add `pytest.mark.asyncio`.
- Import only what is missing — do not duplicate imports.

### Step 7 — Report summary to the user

After writing all files, summarize in a clear table:

```
Semantic Test Coverage Report
─────────────────────────────
Source functions found : 42
Already covered        : 31
Gaps identified        : 11
Skeleton files written : 3

New stubs written to:
  tests/test_generator.py      (2 functions)
  tests/test_analyzer.py       (7 functions)
  tests/test_main.py           (2 functions)
```

## Input Format

The skill accepts natural language requests. Canonical forms:

- "Run test coverage analysis on `./my_project`"
- "Find untested functions in `src/` and write pytest stubs to `tests/`"
- "What am I missing in my test suite?"
- `/semantic-test-coverage --project-path ./my_project --output-dir ./out`

Parameters (all optional — infer defaults from context):

| Parameter | Default | Description |
|-----------|---------|-------------|
| `project_path` | current directory | Root of the project to scan |
| `output_dir` | `tests/` inside project | Where to write generated files |
| `include_private` | `false` | Also generate stubs for `_private` functions |
| `format` | `json` | Gap report format: `json` or `markdown` |

---

## Output Format

1. **Gap report** — `<output_dir>/coverage_gaps.json` (or printed to stdout).
2. **Skeleton test files** — one per source module with gaps, placed in `tests/`.
3. **Console summary** — plain-text table as shown above.

## Error Handling

| Situation | Response |
|-----------|----------|
| `src/` does not exist | Tell the user. Ask for the correct source directory. Do not guess. |
| A `.py` file has a syntax error | Skip it, log a warning in the report, continue scanning the rest. |
| `tests/` does not exist | Create it (with an empty `__init__.py`) before writing skeletons. |
| Existing test file cannot be parsed | Back it up as `test_<module>.py.bak`, then append new stubs to a fresh file. |
| No gaps found | Report "Full coverage detected — no stubs generated." Do not write empty files. |
| File write permission denied | Report the path and error. Do not silently skip. |
